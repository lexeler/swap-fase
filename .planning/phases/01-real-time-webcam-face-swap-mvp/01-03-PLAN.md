<objective>
Build the Walking Skeleton: the thinnest possible end-to-end live face-swap. A V4L2 capture thread pushes the newest webcam frame into a maxsize-1 keep-newest buffer; an inference thread reads the latest frame, swaps the largest face onto a cached target embedding, and writes the result to a `FrameSink`; a minimal PySide6 window paints the live swapped stream via a thread-safe queued signal. Running `run.py` opens the window and shows the user's live face swapped onto a loaded target photo — smoothly, on the GPU. **This is the project's Core Value smoke test.**

For the skeleton the target photo may be supplied via a constant/CLI arg (the full load-photo dialog arrives in Plan 04) — but the live swap, threading, keep-newest latency control, no-face passthrough, and the Qt preview are all REAL and final here.

Purpose: Steps 5–6 of the ROADMAP risk-first build order — the end-to-end live smoke test. Bakes in the 3-thread + keep-newest latency architecture (Pitfall 6) and the FrameSink seam (future vcam) from the start, since retrofitting threading is a rewrite.
Output: `framebuffer.py`, `capture.py`, `sink.py`, `state.py`, `pipeline.py`, a minimal `ui/main_window.py`, the `app.py` composition root, the real `run.py`, and a `capture_fps.py` smoke test.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| /dev/video* → capture thread | Local webcam device; may be busy, metadata-only, or unplugged mid-run. |
| capture thread → inference thread → UI thread | In-process thread boundaries; UI must never block on GPU work. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-10 | Denial of Service | latency accumulation (unbounded queue) | mitigate | maxsize-1 keep-newest `LatestFrameBuffer` drops stale frames; verified flat-latency over 60s (LIVE-02, D-15, Pitfall 6). |
| T-01-11 | Denial of Service | webcam busy / unplugged / metadata-only node crashes app | mitigate | Probe-and-pick a capturable node (Pitfall 9); catch "device busy" with a clear exception; always `cap.release()` in finally on stop/crash (Pitfall 10). |
| T-01-12 | Denial of Service | a single bad frame (no face / decode glitch) crashes the loop | mitigate | No-face → passthrough unchanged (D-18, SWAP-03); per-frame work wrapped so an exception logs and continues, never killing the thread. |
| T-01-13 | Tampering | UI-thread starvation (inference on UI thread) freezes the Wayland window | mitigate | Inference + capture run on their own threads; UI thread only converts+paints via a queued Qt signal (Anti-Patterns 2/6); acceptance asserts no inference/capture code in main_window.py. |
| T-01-14 | Information Disclosure | webcam frames leaking off-machine | accept | Fully local: no network in the frame path; frames live in memory only, never written to disk (privacy constraint). No further control. |
</threat_model>
